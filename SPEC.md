# Asyq League — SPEC

> Конкурсный проект для **Narxoz Incubator 2026**. Современная цифровая версия
> казахской игры «Асық ату» уровня «Великий».
> Дедлайн жёсткий (≈30 часов), работаем фазами; после каждой фазы продукт
> должен быть задеплоен и работать.

## Продукт
Название: «Asyq League» (рабочее; альтернативы: «Алшы», «Сақа»).
Позиционирование: асық ату как современная соревновательная игра — от семейного
обучения до студенческой лиги между университетами Казахстана.
Слоган: «Прицелься. Бросай. Выбивай.»
Языки: қазақша / русский / English (переключатель, по умолчанию — язык браузера).
Все казахские буквы (ә ғ қ ң ө ұ ү һ і) должны корректно отображаться в выбранных шрифтах.

## Главный принцип
Механика важнее графики. Проверяющие будут пробовать разные броски. Бросок
обязан зависеть ТОЛЬКО от направления и силы, заданных игроком, и физика должна
вести себя одинаково и предсказуемо. Никаких заранее заданных анимаций результата.

## Стек (не менять без причины)
- Vite + React + TypeScript (strict).
- Рендер: three.js через @react-three/fiber + @react-three/drei, камера сверху под
  углом ~55° (2.5D). Постэффекты — @react-three/postprocessing (bloom лёгкий, vignette).
- Физика: СОБСТВЕННЫЙ детерминированный 2D-движок в src/physics (чистый TS, без
  зависимостей от React/three). Игра логически 2D (плоскость земли), высота/подскок —
  только визуальная (параболическая дуга полёта сақа + лёгкое вращение).
- Состояние UI: zustand. Анимации UI: framer-motion. Стили: Tailwind.
- Звук: howler.js. Частицы — свои на instanced mesh.
- Бэкенд: Supabase (Auth, Postgres + RLS, Realtime, Edge Functions).
- Хостинг: Vercel. Роутинг: react-router.
- Тесты: vitest для physics и rules (обязательно тест детерминизма).

## Физика (src/physics) — требования

Модель **2.5D**: бросок трёхмерен (сақа летит по дуге, бьётся о землю, отскакивает,
скользит и останавливается), но поле плоское. Коллайдер — сфера, меш рисуется поверх.

- Фиксированный шаг **1/240 c**, лимит 12 c модельного времени. Шаг выбран из условия
  отсутствия туннелирования: при 12 м/с тело проходит за шаг 0.05 м — меньше
  наименьшего радиуса (0.075 м).
- Тело: `pos{x,y,z}`, `vel{x,y,z}`, `radius`, `mass`, `height`, кувыркание `tumble`/`omega`,
  рыскание `yaw`, фаза `air | sliding | resting`.
- Каждый шаг:
  1. **AIR**: `vz -= g*dt`, скорость гасится сопротивлением воздуха;
  2. **удар о землю** (`z <= radius && vz < 0`): `vz = -vz*eGround`; касание съедает
     `mu*(1+eGround)*|vz|` горизонтальной скорости, но **не больше `maxTangentialLoss`
     от неё** — иначе при крутом падении тело замирает в точке приземления;
     потерянное уходит в кувыркание; событие `groundImpact`;
  3. **SLIDING**: замедление `muSlide*g*dt`, при `|v| < vSleep` — покой;
  4. **покой**: кувыркание прилипает к ближайшей четверти — так физически
     определяется алшы / тәйкі / бүк / шік;
  5. **тело-тело**: сфера-сфера в 3D, восстановление ~0.8 плюс касательное трение;
     удар может подбросить асық — это нормально; событие `bodyHit{inAir}`.
- Поверхности (`eGround / mu / muSlide`): **песок** (кампания), **земля** (рейтинг и онлайн),
  **асфальт**, **лёд**. Поверхность задаётся конфигом уровня или режима.
  Купленная арена меняет картинку, но **не физику**.
- Детерминизм: в симуляции только `+ - * /` и `Math.sqrt`. Тригонометрия — один раз
  при формировании броска; `ThrowInput { vx, vy, vz, spin, originX, originY }` квантуется до 1e-4.
  Случайность — только `mulberry32` с seed матча.
- `simulate(state, throwInput) -> { finalState, frames[], events[] }` — чистая функция.
  События: `groundImpact`, `bodyHit{inAir}`, `knockOut`, `nearMiss`, `wallBounce`, `sakaRest{inside}`, `sakaLost`.
- `stateHash(state)` — хеш позиций, скоростей и фаз для проверки синхронизации.
- **Очки считаются ТОЛЬКО по финальному состоянию покоя.** Асық выбит, если остановился
  за границей поля; флаг `scored` ставится один раз. Асық, вылетевший в воздухе,
  но упавший обратно в поле, — не выбит. `knockOut` остаётся только для эффектов.
- Очерёдность: подбрасывание сақа **той же физикой** с отклонениями из seed;
  выпавшая сторона решает, кто начинает (алшы > тәйкі > бүк > шік).
- Тесты: 1000 прогонов одного input → одинаковый hash; закон отскока; энергия не растёт;
  нет туннелирования под любым углом; асық, упавший обратно, не засчитан;
  бросок 5° почти не отрывается от земли, 50° имеет отскоки.

## Правила (показать в приложении экраном «Правила» и в README)
Основа (традиционная, упрощённая для браузера):
1. Кон: асыки выставлены в ряд (или по раскладке уровня) внутри поля — круга
   или квадрата, очерченного мелом.
2. Игрок бросает сақа от линии броска: выбирает направление и силу.
3. Асык считается выбитым, когда его центр полностью покинул границу поля.
   За каждый выбитый асык +1 очко (асык «переходит» игроку). Каждый асык может
   принести очко ТОЛЬКО ОДИН раз (флаг scored, проверить тестом).
4. Выбил хотя бы один — бросаешь ещё раз. Промах — ход переходит сопернику.
5. Если сақа остановилась внутри поля — штраф: −1 очко (один свой асык
   возвращается в кон). В разных дворах это правило разное — пометить как
   вариант правил, который можно отключить в настройках частного матча.
6. Раунд заканчивается, когда кон пуст. Побеждает тот, у кого больше асыков.
   При равенстве — решающий бросок.
7. Очерёдность: перед матчем каждый подбрасывает сақа; сторона, на которую она
   упала (алшы > тәйкі > бүк > шік), определяет, кто начинает. Результат — из seed.

Авторские дополнения (отдельный раздел «Авторские дополнения» в правилах и README):
- Комбо: 2+ асыка одним броском → «Қос!», 3+ → «Керемет!» (+1 бонус только в
  одиночных испытаниях, в рейтинговых матчах бонусов нет).
- Звёзды в испытаниях (1–3) за количество использованных бросков.
- Ежедневное испытание, лига университетов, редактор раскладок.

## Управление

Два жеста, оба работают мышью и касанием (Pointer Events):

1. **Направление** — горизонтальный свайп в любом месте экрана поворачивает бросок
   (±35° от центра кона); камера идёт следом, на земле стрелка направления.
2. **Натяжение** — зажать и тянуть вниз-назад: длина тяги = сила (мёртвая зона + максимум),
   наклон тяги = угол подъёма 0°–60°. Отпустил — бросок, вернул к началу — отмена.
   Резинка рогатки тянется визуально.

Какой это жест, решается по первому заметному движению пальца — отдельных кнопок не нужно.

Клавиатура: `←` `→` — направление, `W`/`S` — угол подъёма, удерживать `Пробел` — сила.
В обучении — кнопки-пресеты «Настильно» (~5°), «Средне» (~25°), «Высоко» (~50°).

Подсказка траектории считается тем же модулем физики, но **без столкновений**:
обучение — полная дуга и кольцо первого касания, испытания — 35 % дуги с кольцом,
ежедневное и рейтинг — 20 % без кольца.

Камера — модуль `cameraDirector` с состояниями и плавными переходами: прицеливание
за спиной игрока, натяжение на три четверти сбоку (сақа в левой трети кадра, кон в правой),
полёт с сопровождением и авто-кадрированием, момент удара с наездом, итог сверху.
Кнопка «вид сверху» на всех игровых экранах. FOV 55 в портрете, 45 в альбоме.

## «Сок» (эффекты) — важно, это делает игру живой
- Удар: звук «щелчка кости» (несколько вариаций, питч зависит от скорости),
  искры/пыль частицами, лёгкий camera shake пропорционально импульсу.
- Выбивание: асык вылетает за линию, всплывающий «+1», звук монетки-колокольчика,
  трек ачивок.
- Момент удара: **hit-stop** 60–90 мс, затем слоу-мо (0.55x на одиночном попадании,
  0.3x на комбо), наезд камеры к точке столкновения, ударная волна кольцом по земле.
- Комбо в четыре ступени: «Жақсы!» / «Қос!» / «Керемет!» / «Ғажап!» — каждая громче,
  дольше и тряснее. Попадание по асыку в воздухе — «Тура!».
- Выбивание: меловая пыль на линии, «+1», асық улетает дугой в копилку игрока в HUD,
  вибрация (navigator.vibrate).
- Сақа в полёте: след (trail), тень на земле, которая сжимается при подъёме.
- Приземление: облачко пыли, отпечаток на песке, исчезающий через несколько секунд.
- Победа: конфетти в цветах флага (голубой + золото), экран итогов со статистикой
  (точность, лучший бросок, серия), кнопки «Ещё раз» и «Поделиться».
- UI: орнамент (қошқар мүйіз) как тонкий декоративный элемент в рамках, не перегружать.
- Звук разведён по шинам music / ambience / sfx / crowd с отдельными громкостями,
  стереопанорамой и ограничением одновременных голосов.
- Настройка эффектов в три ступени: полные / умеренные / минимум.
  `prefers-reduced-motion` укорачивает hit-stop и слоу-мо, снимает тряску и наезд.

## Режимы
1. Обучение (3 шага, 1–2 минуты): прицелься → выбери силу → выбей асык из кона.
   Интерактивные подсказки, нельзя провалить.
2. Испытания (кампания): 24 уровня в 4 главах (Аул, Двор, Город, Дала), разные
   раскладки (ряд, пирамида, круг, «крепость», движущийся асык, узкий проход,
   ограниченная сила, ветер-наклон поля в последней главе). 1–3 звезды.
   Плавное усложнение. После неудачи — совет, как улучшить бросок
   («слишком сильно — сақа вылетела», «целься в край асыка для рикошета»).
3. Ежедневное испытание: одна раскладка и seed для всех на день
   (генерация из даты), одна зачётная попытка, таблица лидеров дня.
4. Игра вдвоём на одном устройстве (hot-seat).
5. Онлайн-матч с другом по ссылке + рейтинговые матчи (ELO) — фаза 5–6.
6. Редактор испытаний: расставить асыки, задать форму поля, число бросков,
   цель (сколько выбить) → сохранить → получить ссылку/QR и отправить другу.
   Лента популярных пользовательских испытаний.
7. Лига университетов: в профиле выбрать вуз (Narxoz, KBTU, SDU, AITU, KazNU, ...),
   общий рейтинг вузов = сумма очков ежедневных испытаний и рейтинговых побед
   студентов за неделю.
8. Частные турниры (платная функция, тестовый режим): создать турнир на 4/8/16
   игроков, сетка на выбывание, ссылка-приглашение, свои правила
   (вкл/выкл штраф за сақа в поле, форма кона).

## Мультиплеер (синхронизация бросков)
- Матч по ссылке `/m/:id`. Создатель — player1, открывший ссылку — player2.
- Ход: бросающий симулирует локально → вставляет move {input, result_hash}.
  RLS/функция в Postgres разрешает вставку только если player_id == current_turn.
- Второй клиент получает move через Realtime (postgres_changes), прогоняет ТОТ ЖЕ
  `simulate()` с тем же input и сравнивает hash. При расхождении — берёт state
  из БД (авторитетный) и логирует рассинхрон.
- Переподключение: при открытии страницы состояние восстанавливается из matches.state
  + moves. Индикатор «соперник онлайн» через Realtime Presence.
- Рейтинговые матчи: очередь поиска (таблица queue), ELO K=32. Пересчёт рейтинга —
  Edge Function, которая переигрывает все moves тем же модулем src/physics
  (общий код) и только потом начисляет рейтинг — защита от подмены результата.

## Качество
- 60 fps на среднем Android: InstancedMesh для асыков, тени только от сақа и асыков
  (baked-текстура земли), dpr ограничить [1, 2].
- Мобильная вёрстка first, landscape и portrait. Кнопки ≥ 44px.
- Экран загрузки с прогрессом, ленивые ассеты.
- PWA (manifest + иконки), OG-картинка для красивого превью ссылки в Telegram/WhatsApp.
- Обработка ошибок сети в онлайне: понятные сообщения, не белый экран.
- README.md: что создано и для кого, правила и адаптация для браузера, авторские
  дополнения, инструкция запуска, технологии, AI-инструменты, заимствованные
  ассеты с лицензиями, известные ограничения, тестовый доступ, архитектура
  детерминированной физики (схема).

## Процесс
Работаем по фазам, которые присылает заказчик. В конце каждой фазы: запустить тесты,
сборку (`npm run build`), перечислить, что сделано и что проверить руками.
