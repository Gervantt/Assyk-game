# Asyq League — «Асық ату»

**Прицелься. Бросай. Выбивай.**

Современная цифровая версия казахской дворовой игры **асық ату**. Проект для
**Narxoz Incubator 2026**. Играется в браузере, на телефоне и на компьютере,
на трёх языках: **қазақша / русский / English**.

> Статус: **Фаза 3** — обучение, кампания из 24 уровней, звёзды, советы после неудачи.
> Онлайн и Supabase появятся в следующих фазах (см. [SPEC.md](SPEC.md)).

---

## Для кого это

- **Для детей и родителей** — способ познакомиться с игрой, в которую играли во дворах,
  без необходимости искать настоящие асыки.
- **Для студентов** — соревновательный режим: лига между вузами Казахстана (впереди).
- **Для всех** — быстрый матч на одном телефоне вдвоём.

## Правила и как они адаптированы для браузера

### Традиционные правила

1. Асыки выставляются в **кон** — круг, очерченный мелом.
2. Игрок бросает **сақа** от линии броска, выбирая направление и силу.
3. Асық считается выбитым, когда его **центр полностью покинул границу кона**: +1 очко.
   Каждый асық приносит очко **только один раз**.
4. Выбил хотя бы один — бросаешь ещё раз. Промах — ход переходит сопернику.
5. Если сақа **остановилась внутри кона** — штраф: −1 очко, один свой асық возвращается в кон.
   В разных дворах это правило разное, поэтому оно вынесено в **варианты правил** и отключается.
6. Раунд заканчивается, когда кон пуст. Побеждает тот, у кого больше асыков.
   При равенстве — решающий бросок.
7. Очерёдность: каждый подбрасывает сақа, сторона решает, кто начинает —
   **алшы > тәйкі > бүк > шік**. Результат подбрасывания берётся из seed матча.

### Что пришлось адаптировать

| В жизни | В браузере | Почему |
|---|---|---|
| Бросок рукой: замах, кисть, щелчок | «Рогатка»: зажать, потянуть назад, отпустить | Пальцем на телефоне нужен жест, который читается одинаково и мышью, и касанием |
| Асық — объёмная кость с четырьмя сторонами | Круговой коллайдер + сторона падения из seeded PRNG | Честная 3D-физика кости была бы недетерминированной и непредсказуемой для игрока |
| Подскоки и высота полёта | Высота — **только визуальная** парабола, физика логически 2D | Механика должна быть одинаковой и воспроизводимой на любом устройстве |
| Сторона, на которую лёг асық | Розыгрыш из `mulberry32(seed)` | Матч можно переиграть по записи бросков и получить тот же результат |
| Площадка во дворе | Мир ограничен: тело, вышедшее за границу, выбывает | Иначе симуляция может не остановиться |

### Авторские дополнения

- **Комбо**: 2 асыка одним броском — «Қос!», 3 и больше — «Керемет!»
  (+1 бонус только в одиночных режимах, в рейтинговых матчах бонусов нет).
- Звёзды за экономию бросков в испытаниях, ежедневное испытание, лига вузов,
  редактор раскладок — в следующих фазах.

## Архитектура детерминированной физики

Главный принцип проекта: **бросок зависит только от направления и силы, заданных игроком.**
Никаких заранее записанных анимаций результата — на экране проигрывается то, что посчитала симуляция.

```
   игрок тянет «рогатку»
            │
            ▼
   ┌────────────────────┐   ЕДИНСТВЕННОЕ место с sin/cos.
   │  aim.ts            │   Направление и сила превращаются
   │  aimFromPull()     │   в скорость и КВАНТУЮТСЯ до 1e-4.
   │  makeThrow()       │
   └─────────┬──────────┘
             │  ThrowInput { vx, vy, originX, originY }   ← по сети уходит именно это,
             │                                              а не угол и не пиксели тяги
             ▼
   ┌──────────────────────────────────────────────┐
   │  simulate(state, input)  — ЧИСТАЯ ФУНКЦИЯ    │
   │  ┌────────────────────────────────────────┐  │
   │  │ цикл: шаг 1/120 с, пока всё не встанет │  │
   │  │  1. трение качения  (линейное)         │  │
   │  │  2. интегрирование  x += v*dt          │  │
   │  │  3. столкновения кругов, e = 0.8       │  │
   │  │  4. границы мира                       │  │
   │  │  5. выход центра за кон -> knockOut    │  │
   │  │                                        │  │
   │  │  разрешены только  + - * /  и  sqrt    │  │
   │  │  запрещены sin/cos/atan/pow/random     │  │
   │  └────────────────────────────────────────┘  │
   └───────┬───────────────┬───────────────┬──────┘
           │               │               │
      finalState       frames[]        events[]
           │               │               │
           ▼               ▼               ▼
     stateHash()      анимация        очки, эффекты,
     (сверка)         в сцене         подсказки
```

**Почему это работает одинаково во всех браузерах.** Операции `+ - * /` и `Math.sqrt`
определены стандартом IEEE-754 побитово точно, а `Math.sin/cos/atan/pow` — нет:
их реализация отличается между движками и платформами, и одна и та же формула может
дать разный последний бит. Поэтому тригонометрия применяется **один раз** при переводе
прицела в скорость, результат сразу квантуется до `1e-4`, и дальше вся симуляция
работает только с безопасными операциями.

**Случайность.** `Math.random()` в проекте запрещён. Всё случайное (сторона, на которую
лёг асық; жеребьёвка) берётся из `mulberry32(seed)`, где seed хранится в матче.

Это даёт три вещи, нужные для следующих фаз:
1. Онлайн-матч синхронизируется передачей одного `ThrowInput` — оба клиента считают одно и то же.
2. `stateHash(state)` позволяет заметить рассинхрон.
3. Edge Function на сервере может переиграть все ходы **тем же кодом** и проверить результат.

Проверяется тестами: `npm test` прогоняет один бросок **1000 раз** и сверяет хеш,
держит снимок на 20 разных бросков и отдельно проверяет воспроизводимость
сценариев с камнями, ветром и движущимся асыком.

## Запуск

Нужен Node.js 18+.

```bash
npm install
npm run dev        # http://localhost:5173
```

Другие команды:

```bash
npm test           # тесты физики и правил (vitest)
npm run build      # production-сборка в dist/
npm run preview    # посмотреть собранную версию
npm run typecheck  # TypeScript strict
```

Пересобрать модель асыка:

```bash
node scripts/make-asyk-glb.mjs   # -> public/models/asyk.glb
```

## Управление

- **Мышь и касание:** зажать в любой точке поля, потянуть **назад** и отпустить.
  Направление броска — противоположно вектору тяги, сила — длина тяги.
  Вернуть палец в центр — бросок отменится (мёртвая зона).
- **Клавиатура:** `←` `→` — угол, удерживать `Пробел` — набор силы, отпустить — бросок.
- Короткий пунктир показывает **только направление и примерно 20 % пути** — это подсказка,
  а не предсказатель траектории.
- Кнопка **«Сверху» / «От игрока»** переключает камеру.

## Ассеты

### Модель асыка

`public/models/asyk.glb` — **параметрическая заглушка**, сгенерированная скриптом
(`node scripts/make-asyk-glb.mjs`), а не скан настоящей кости: вытянутое тело
с двумя утолщениями по краям, талией, выпуклой стороной (бүк) и вогнутой (шік).
1620 треугольников.

Чтобы поставить свою модель, достаточно **положить свой `asyk.glb` в `public/models/`** —
менять код не нужно. Загрузчик сам приведёт её к нужному виду: наибольший габарит
масштабируется в 1, центр переносится в начало координат. Сақа — **тот же меш**,
отличается только материалом и размером.

Если файла нет или он битый, игра молча переходит на примитив и не показывает
белый экран.

### Земля, небо и звук

| Ресурс | Как сделан |
|---|---|
| Текстура песка + карта нормалей | генерируются кодом (`src/game/scene/textures.ts`): бесшовный value-noise 512×512, четыре октавы |
| HDRI неба | процедурная равнопромежуточная панорама степного неба, прогнанная через `PMREMGenerator` (`SteppeEnvironment.tsx`) — без внешнего `.hdr` и без CDN |
| Звуки | синтезируются в WAV прямо в браузере (`src/audio/synth.ts`): щелчок кости в трёх вариациях, монетка, арпеджио комбо, свист, глухой удар, штраф, фанфара, клик |

Такой подход выбран сознательно: в репозитории нет тяжёлых бинарных ассетов,
нет внешних зависимостей при загрузке и нет лицензионных вопросов.

## Обучение и кампания

### Обучение — три шага, провалить нельзя

1. **Прицелься** — зажать и потянуть назад; бросок не засчитывается, пока пунктир
   не смотрит на кон, и игре есть что подсказать.
2. **Выбери силу** — на шкале подсвечена зона, в которую нужно попасть.
3. **Выбей асық** — броски не ограничены, шаг засчитывается по первому выбиванию.

Неудачный бросок не отнимает ничего: он просто не принимается, и рядом появляется
объяснение, что поправить. В обучении пунктир прицела **длиннее**, чем в обычной игре.

### Кампания — 24 уровня в 4 главах

| Глава | Что появляется |
|---|---|
| **Ауыл / Аул** | основы: ряд, пирамида, круг, большой кон, запас бросков |
| **Аула / Двор** | квадратный кон, кон поменьше, плотные раскладки, меньше бросков |
| **Қала / Город** | каменные преграды, «крепость», узкий проход, **движущийся асық** |
| **Дала / Степь** | **наклон поля (ветер)**, **ограниченная сила**, всё вместе в финале |

- **Звёзды 1–3** — за экономию бросков. Пороги заданы в уровне: `stars: [на 3, на 2]`.
- **Блокировка** — следующий уровень открывается после прохождения предыдущего.
  Прогресс в `localStorage`, облако появится в Фазе 5.
- **Советы после неудачи** выводятся **только из событий симуляции**, без догадок:

| Что показала симуляция | Совет |
|---|---|
| `sakaLost` — сақа вышла за пределы мира | «Слишком сильно, убавь силу» |
| сақа встала перед коном, поперечное отклонение мало | «Недолёт, добавь силы» |
| сақа встала далеко в стороне | «Мимо, точнее выбирай направление» |
| был удар по асыку, но `knockOut` не случился | «Задел, но не выбил — целься в край для рикошета» |
| `sakaStoppedInside` | «Сақа осталась в кону — бей в край» |
| на уровне есть движущийся асық и не было удара | «Бери упреждение, важен тайминг» |

За уровень показывается самый частый совет — то, что игрок повторяет из броска в бросок.

### Уровни описаны в JSON

Все уровни лежат в [src/levels/chapters/](src/levels/chapters/) — по файлу на главу.
Чтобы добавить уровень, достаточно дописать объект; код менять не нужно.

```jsonc
{
  "id": "qala-3",
  "layout": { "kind": "circle", "count": 5, "fieldRadius": 1.3 },
  //         kind: row | pyramid | circle | square
  //         shape: circle | square — форма кона
  "throws": 5,            // бюджет бросков
  "goal": 3,              // сколько асыков надо выбить
  "stars": [3, 4],        // [порог на 3 звезды, порог на 2 звезды]
  "penalty": false,       // отключить штраф за сақа в кону
  "maxPower": 0.78,       // ограничение силы, 0..1
  "wind": { "x": 0.7, "y": 0 },              // наклон поля, м/с²
  "obstacles": [{ "x": 0, "y": -0.9, "radius": 0.19 }],   // камни
  "movers": [{ "x": 0, "y": 0.45, "axis": "x", "amplitude": 0.5, "periodSec": 1.8 }]
}
```

Описания проверяются при загрузке ([validate.ts](src/levels/validate.ts)): опечатка
в JSON даёт понятную ошибку, а не молчаливо сломанный уровень.

### Уровни проверяются перебором, а не на глаз

Тест [solvable.test.ts](src/levels/__tests__/solvable.test.ts) прогоняет **каждый**
уровень лучевым поиском по настоящим правилам — через `applyThrow`, то есть со штрафом
за сақа в кону. Он утверждает две вещи:

1. уровень проходится в отведённые броски;
2. порог на две звезды достижим идеальным игроком.

Это не формальность: при первом прогоне тест нашёл **четыре непроходимых уровня**
(камень перекрывал все линии к асыкам; при ограниченной силе асыки не вылетали
за границу кона; цель была выше достижимой) — их пришлось переделать.

## Эффекты («Сок»)

| Эффект | Как реализовано |
|---|---|
| Щелчок кости при ударе | три вариации, высота тона и громкость зависят от импульса столкновения |
| Искры и пыль | один `InstancedMesh` на 130 частиц, один draw call |
| Тряска камеры | амплитуда пропорциональна импульсу, две несоизмеримые частоты |
| Слоу-мо на комбо | 0.3× на 0.6 с; планируется заранее — события броска уже посчитаны, поэтому известно, будет ли мульти-выбивание |
| Наезд камеры на комбо | плавный зум до 0.72 на время замедления |
| След за сақа | кольцевой буфер последних 16 позиций |
| Тень-пятно под сақа | сжимается и светлеет, когда сақа в воздухе |
| Отпечаток на песке | до 10 отпечатков, растворяются за 4.5 с |
| Тени | направленный свет, карта 2048² |
| Надписи | «Ұтып алдың!», «Қос!», «Керемет!» — крупным шрифтом, плюс «+1» над выбитым асыком |
| Вибрация | `navigator.vibrate` на выбивании, комбо, штрафе и победе |
| Конфетти | цвета флага (#00AFCA + #FEC50C), canvas 2D поверх экрана итогов |

Всё это отключается одним переключателем **Настройки → Эффекты → Уменьшенные**
(он же автоматически включается при системной настройке `prefers-reduced-motion`).

## Производительность

Замеры сделаны в headless-Chromium на эмуляции Pixel 5. Важная оговорка:
headless использует **SwiftShader — софтверный растеризатор**, поэтому абсолютный
fps там не показатель для настоящего мобильного GPU. Что измерено достоверно:

**Нагрузка на GPU (это и предсказывает fps на железе):**

| Режим | draw calls | треугольников | пикселей |
|---|---|---|---|
| Полные эффекты | 9 | ~13 000 | dpr ≤ 2 |
| Уменьшенные | 6 | ~9 900 | dpr ≤ 1.5, проход теней выключен |

**Нагрузка на CPU (наш JS):** при малом числе пикселей игра держит ровно
**60 fps (16.7 мс на кадр) даже при 6-кратном троттлинге процессора**. То есть
выборка кадров симуляции, частицы, след и камера укладываются в бюджет кадра
с большим запасом.

**Что упирается в софтрендер:** fps линейно падает с числом пикселей —
0.08 Мпикс → 60 fps, 0.18 → 57, 0.33 → 36, 1.34 → 13. Это чистая заливка,
которую на реальном устройстве делает GPU.

Переключатель «Уменьшенные эффекты» даёт реальный выигрыш: в том же софтрендере
**12 → 26 fps**, потому что снимает 44 % пикселей и убирает проход теней.

> **Проверить на своём телефоне обязательно.** Подтвердить «60 fps на среднем
> Android» из headless-окружения нельзя, и я этого не утверждаю.

## Что сделано в Фазе 1

- Детерминированный физический движок с тестами воспроизводимости.
- Правила: очки, флаг `scored` (асық приносит очко один раз), штраф за сақа в кону
  с возвратом асыка, передача хода, условие победы, жеребьёвка из seed.
- Сцена 2.5D на временных примитивах: земля, меловой кон, линия броска,
  асыки на `InstancedMesh`, сақа отдельным цветом.
- Управление «рогатка» мышью и касанием + клавиатура, короткий пунктир, шкала силы.
- Режим **«Тренировка»**: 5 асыков, 5 бросков, счёт, экран итогов, перезапуск.
- Режим **«Вдвоём»** (hot-seat) на одном устройстве.
- Лучший результат в `localStorage`.
- Три языка с автоопределением по языку браузера.

## Что сделано в Фазе 2

- Модель асыка из `public/models/asyk.glb` (сақа — тот же меш, другой материал),
  генератор модели скриптом, загрузчик с фолбэком.
- Текстура земли с картой нормалей и процедурный HDRI степного неба.
- Весь раздел «Сок»: звуки, частицы, тряска камеры, слоу-мо и наезд на комбо,
  след, тень-пятно, отпечатки, тени, конфетти, вибрация, надписи на казахском.
- Экран настроек: звук, громкость, уровень эффектов, вибрация, язык.
  Всё сохраняется в `localStorage`.
- Быстрые кнопки звука и камеры прямо в игре.
- Замеры производительности на мобильном эмуляторе (см. раздел выше).

## Что сделано в Фазе 3

- Интерактивное обучение из трёх шагов, которое нельзя провалить.
- Кампания: 24 уровня в 4 главах, описанные в JSON, со звёздами и блокировкой.
- Советы после неудачи, выведенные из событий симуляции.
- Расширения физики под разнообразие уровней, все детерминированные:
  **камни-препятствия** (бесконечная масса), **наклон поля** (постоянное ускорение,
  действует только на катящееся тело — лежащее держит трение покоя) и
  **движущийся асық** (треугольная волна от номера тика; при первом касании
  срывается и дальше живёт обычной физикой).
- Автоматическая проверка проходимости всех 24 уровней перебором.
- 101 тест.

## Известные ограничения (Фаза 2)

- Прогресс кампании живёт только в `localStorage` этого браузера.
- Модель асыка — **сгенерированная заглушка**, а не скан настоящей кости.
  Заменяется подкладыванием своего `asyk.glb` (см. раздел «Ассеты»).
- Вибрация не работает в Safari на iOS — там нет `navigator.vibrate`.
- «60 fps на среднем Android» не подтверждено измерением: headless-окружение
  рисует софтверно. Нужна проверка на живом устройстве.
- Нет аккаунтов, облачного прогресса и онлайна: прогресс живёт только в `localStorage`
  этого браузера. Supabase подключается в Фазе 5.
- Нет ежедневного испытания, редактора уровней и лиги вузов.
- Нет PWA-манифеста и OG-картинки.
- Штраф по правилу 5 включён по умолчанию, и точное попадание в центр асыка часто
  гасит сақа внутри кона. Это соответствует настоящей игре (нужно целиться в край,
  чтобы уйти рикошетом), но в Фазе 2 к этому добавится подсказка для новичка.
